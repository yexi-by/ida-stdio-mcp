# ida-stdio-mcp 能力矩阵

本文档描述 ida-stdio-mcp 在 **IDA 9.3+ headless + stdio MCP** 形态下对外承诺的能力边界。默认 `all` 工具面注册全部能力；`workflow` 工具面只展示完成开局分析、定点调查、函数解释、报告导出和工作区管理所需的高层入口。

注意：当前矩阵描述的是工具面边界，不等同于“当前环境一定可用”。IDA runtime、debugger backend、Hex-Rays、managed decompiler 和 external analyzer 都通过统一能力状态显式探测；缺失时返回结构化 `unsupported`、`misconfigured` 或 `unavailable`，不能把工具注册伪装成能力可用。

## 能力初始化入口

| 入口 | 说明 |
| --- | --- |
| `runtime_health` | 不要求活动会话，分层诊断 `idapro` 包、`idalib.dll`、`IDADIR`、IDA 版本和安装目录。 |
| `get_capability_state` | 返回 `ida_runtime`、`open_target`、`debugger`、`hexrays`、`managed_decompiler`、`external_analyzers` 的统一快照。 |
| `debug_health` | 在 headless 流程内按工具参数、配置、环境变量或平台默认值尝试加载调试器后端，并返回 backend attempts、request 队列和 `DSTATE_*` 映射后的状态。 |

## AI 工作流能力

| 能力 | workflow | all | 说明 |
| --- | --- | --- | --- |
| 工作区状态摘要 | 可用 | 可用 | `get_workspace_state` 返回 runtime、session、working IDB、最近目标与推荐下一步 |
| 打开样本 | 可用 | 可用 | `open_target` 完整加载样本和调试符号，创建 `.runtime/sessions/<session_id>/working.i64`；支持 loader、processor、plugin options 的 headless 参数；默认不等待全库自动分析 |
| 开局 triage | 可用 | 可用 | `triage_binary` 默认不构建全量字符串索引 |
| 字符串牵引调查 | 可用 | 可用 | `investigate_string` 返回字符串、xref、所属函数闭环 |
| 函数解释 | 可用 | 可用 | `explain_function` 聚合画像、伪代码、调用关系与可选 microcode 线索 |
| 输入到检查点追踪 | 可用 | 可用 | `trace_input_to_check` 做轻量 xref / 函数关系追踪 |
| 报告导出 | 可用 | 可用 | `export_report` 面向 AI 复盘 |
| 工作区保存 | 可用 | 可用 | 默认保存 working IDB；显式 path 才导出到用户路径 |

推荐调用顺序：

```text
get_workspace_state -> open_target -> triage_binary -> investigate_string / explain_function -> export_report
```

## 底层 IDA 能力

| 能力 | native | managed/.NET | workflow | all | 说明 |
| --- | --- | --- | --- | --- | --- |
| 函数枚举 | full | full | 通过 triage/explain 间接使用 | 工具已注册 | `list_functions` 等底层工具在 `all` 工具面暴露；实际可用性取决于 IDA runtime 与当前 working IDB |
| 反编译 | Hex-Rays / 汇编降级 | ilspycmd C# / IL 降级 | `decompile_function` 可用 | 工具已注册 | 结果带 representation、backend、confidence；Hex-Rays / ilspycmd 通过统一能力状态探测 |
| 调用图 | full | degraded | 通过 triage/explain 间接使用 | 工具已注册 | managed 主要基于符号与 IL/反汇编线索 |
| 字符串 | full | degraded | 定点调查可用 | 全量工具可用 | 字符串工具为当前 working IDB 构建受控缓存；响应包含 data/cache/statistics |
| 导入表 | full | partial | triage 中摘要 | `list_imports` / `get_import_at` | 9.3+ 优先 import-by-address 富化 module/name/ordinal |
| 类型/结构体 | full | degraded | explain/report 中摘要 | 工具已注册 | 托管写回边界需看质量等级 |
| 写回/补丁 | full | partial | 不展示直接入口 | 工具已注册 | 注释、重命名、类型、补丁作用于 working IDB；`patch_diff`、`patch_history`、`rollback_patch` 提供预览、记录和回滚便利 |
| IDAPython | full | partial | 不展示直接入口 | 工具已注册 | `evaluate_python` / `execute_python_file` 绑定当前或指定 session，大结果自动写入 artifact |
| 调试器 | backend dependent | backend dependent | 不展示直接入口 | 工具已注册 | `debug_health`、`debug_launch`、`debug_attach` 在 headless 流程内加载 backend；寄存器、栈、内存、栈回溯只在目标 suspended 时执行 |
| dispatcher 扫描 | heuristic | heuristic | 不展示直接入口 | 工具已注册 | `scan_dispatchers` 识别通用 hash/switch/table/indirect-call 分发候选 |
| 外部 artifact 关联 | config dependent | config dependent | 不展示直接入口 | 工具已注册 | `run_external_analyzer`、`import_analysis_artifact`、`correlate_analysis_artifact` 连接本地分析 JSON 与 IDB 证据；analyzer 命令入口、超时、非 JSON 输出都显式分类 |
| microcode 只读线索 | Hex-Rays dependent | unavailable | 通过 explain 可选 | 工具已注册 | summary/def-use 标记为 experimental；Hex-Rays 插件/license/架构状态通过统一探测返回 |
| microcode mutation | experimental | unavailable | 不展示直接入口 | 实验入口 | 结果必须标记为 experimental，并通过伪代码或函数解释复核；默认不作为稳定能力承诺 |

## Runtime 与会话状态

| 字段 | 说明 |
| --- | --- |
| `source_path` | 原始样本路径 |
| `working_idb_path` | 当前会话工作 IDB，固定在 `.runtime/sessions/<session_id>/working.i64` |
| `dirty` | 当前工作库是否存在未保存写回 |
| `last_active_tool` | 最近成功活动工具 |
| `recent_targets` | 最近分析过的函数、地址、字符串或路径 |
| `recommended_next_tools` | 服务端基于最近活动给 AI 的下一步建议 |
| `metadata` | 打开结果报告：加载状态、working IDB 状态、自动分析等待状态、PDB 线索、耗时、入口数量和 segment 预览 |

## 输出契约

| 工具 | 响应重点 |
| --- | --- |
| `list_strings` / `find_strings` / `search_regex` | 返回 `data`、`next_offset`、`statistics`、`cache`、`recommended_next_tools`；`limit` / `count` 只控制返回行数 |
| `investigate_string` | 返回匹配字符串、xref、所属函数和字符串缓存状态 |
| `evaluate_python` | 返回受控大小的 `stdout`、`stderr`、`result`、`local_keys`，`include_locals=true` 只增加可序列化摘要；大 `stdout`、`stderr` 或 `result` 会写入 artifact 并返回 `path`、`sha256`、`size`、`schema` |

## 上下文隔离

默认共享上下文适合单 agent 串行分析。启用 `--isolated-contexts` 后：

- session 归属按 `context_id` 隔离。
- 会话相关工具和资源必须提供 `context_id`。
- `get_workspace_state` 只返回当前上下文可见 session。
- `close_target`、`save_workspace` 只能操作当前上下文拥有的 session。

缺少 `context_id` 时服务按 Fail-Fast 策略返回结构化错误，共享上下文不会接管隔离请求。
