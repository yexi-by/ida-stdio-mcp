# 验证记录

核对日期：2026-07-25。当前版本尚未完成 `1.0.0` 整体验收；本文件定义可复现命令与
证据要求，不把局部通过等同于产品支持。

## 工具链

- Python：3.13；
- 包与环境：uv lock；
- 格式与静态检查：Ruff、basedpyright strict；
- 测试：pytest、Hypothesis；
- fixture 编译器：LLVM/LLD 22.1.8；
- IDA 门禁：受许可的 IDA Pro 9.3+ headless 与对应 decompiler。

开发虚拟环境放在工作树外：

```powershell
$env:UV_PROJECT_ENVIRONMENT = "$env:LOCALAPPDATA\ida-re-mcp\dev-venv"
uv python install 3.13
uv sync --locked
```

## 普通质量门禁

```powershell
./scripts/run_quality.ps1
```

该脚本依次检查：

1. lock 与 Python 3.13；
2. Ruff format/check；
3. basedpyright strict；
4. `tests/unit` 与 `tests/integration`；
5. fixture 双目录可复现性；
6. wheel 构建、隔离安装和 current-only stdio smoke。

普通 CI 在 GitHub 托管 Windows runner 上执行同一组步骤，不读取 IDA 许可证。
`tests/integration` 必须使用真实 subprocess stdio，并以官方 current-mode client 覆盖工具、
resource 与错误路径。

### 2026-07-25 本机候选验证

在 Python 3.13.14、IDA Pro 9.3 与对应 decompiler 许可环境中，已得到以下结果：

- `./scripts/run_quality.ps1` 通过：Ruff format/check、basedpyright strict、
  `tests/unit` 与 `tests/integration` 共 337 项通过；
- fixture 在两个工作树外目录独立构建，产物与仓库 `SHA256SUMS` 完全一致；
- sdist 与 wheel 构建通过，wheel 在隔离的 Python 3.13 环境安装成功；
- 安装后 current-only stdio smoke 通过，stdout 只有一条协议响应；
- IDA 静态、mutation、IL2CPP 与 Expert 批次 11 项通过；
- Windows 本机 x64 debugger 批次 6 项通过。

这些结果证明当前候选实现的本机硬门禁通过，不替代正式 MCP 规范、稳定 SDK 和支持
current 协议的 Inspector 三项发布门禁。

同一 data root 的进程门禁必须证明：

- `serve`、`doctor` 与 `gc` 获取同一个 Supervisor owner lease；
- 第二个进程在读取或修改 operation 前失败；
- owner 崩溃后新进程可获取 lease；
- revision 已提交时从 operation 提交凭据恢复成功结果，未提交时以
  `worker_crashed` 终结。

存储门禁必须覆盖持久 AnalysisWorker 的复用、空闲退出、失败后 checkout 清理，以及
GC 对未保留 revision、孤立 artifact/change set/staging 的 dry-run/apply 一致性。
current、配置保留的 revision 与 pinned export 必须始终保留；chunk index 中每个 URI、
offset、size 和 SHA-256 都必须通过读取校验。

## MCP Inspector 门禁

截至 2026-07-25，验收环境中的 `@modelcontextprotocol/inspector@0.21.2` 发送的协议
版本不是 `2026-07-28`。真实 stdio 请求得到预期 `-32602`，因此该版本不能作为正向
Inspector 门禁，也不能通过服务端增加其他协议分支绕过。

正式发布前必须使用支持正式 `2026-07-28` 的 Inspector 重新执行 tools、resources、
严格 schema、输出校验和 stdout 纯净验收。当前正向协议证据由官方 current-mode
Python client 提供；Inspector 缺口保持为外部阻塞。

## Fixture

```powershell
./scripts/build_fixtures.ps1
./scripts/check_fixture_reproducibility.ps1
```

fixture 全部来自仓库内自有源码，包括 PE x64、ELF x64、AArch64 ELF、Windows x64
调试目标和 IL2CPP-shaped PE/ELF。构建器固定为 LLVM/LLD 22.1.8，启用确定性链接参数，
并要求两个独立输出目录的 `SHA256SUMS` 完全一致。

提交的 fixture 二进制必须与 `tests/fixtures/bin/SHA256SUMS` 匹配。构建产生的 `.obj`
与导入库不会保留。

## IDA 静态与 mutation 门禁

自托管 runner 必须显式提供 `IDADIR`，且 `doctor`/worker probe 确认 IDA 9.3+
headless 可用。执行：

```powershell
uv run --locked pytest -q tests/ida -m "ida and not debugger"
```

证据必须覆盖：

- bootstrap 后私有 checkout 的关闭语义；
- PE x64、ELF x64、AArch64 ELF 的镜像与函数事实；
- 函数 chunks、xref 类型、UDT/原型、ctree 地址映射；
- MAY/MUST def-use、前后向 slice 和 unknown barrier；
- mutation 与 IL2CPP 写入的回读；
- 每个候选 revision 冷重开后对原样本 SHA-256、架构、位宽、端序、镜像大小和组件
  哈希的验证；
- revision 发布与 HEAD、样本摘要不变量。

不得用整段伪代码文本作为稳定断言。

## Windows x64 debugger 门禁

```powershell
uv run --locked pytest -q tests/ida -m debugger
```

证据必须来自真实 IDA 事件并覆盖：

- headless debugger backend 加载；
- PROCESS_STARTED/ATTACHED 与 module+rva 的 ASLR 映射；
- `debug.establish`、控制动作和 `debug.finish` 返回
  `completion_kind`、`completion_provenance` 与 `observed_event_sequence`；
- active 断点与真实 BREAKPOINT；
- RIP/RSP、线程、调用栈、栈内存、已知内存和内存映射；
- pause、step_into、step_over、run_to、continue；
- 正常退出、detach、非法 PID、提前退出和无效内存；
- worker 崩溃后的 Job Object 进程树清理；
- 全程无 GUI、弹窗和 stdout 污染。

IDA 与 debugger 门禁不得使用 skip 或 xfail。缺失运行时、后端、许可证或必要 decompiler
必须使门禁失败。自托管 IDA workflow 同时由 push、pull request 与手动触发，仓库分支
保护必须把该 workflow 设为必需检查。
